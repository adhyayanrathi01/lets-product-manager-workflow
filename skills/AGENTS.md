# Skill rules

- Keep every skill provider-neutral and focused on a reusable process.
- Discover available tools and data access at runtime.
- Prefer evidence-backed outputs over generic advice.
- Stop for PM judgment when a workflow reaches prioritization or product decision-making.
- Do not add provider-specific folders unless a future workflow genuinely cannot remain portable.
- Improve skills only with generalizable, non-sensitive, non-duplicative learnings.
- Give each skill a concise contract covering required inputs, readiness checks, output or artifact, partial-result behavior, and blocking conditions.
- Mark task-relevant capabilities ready, partial, or blocked from context.md instead of treating connection presence as readiness.
- Use skills/evidence/evidence-handoff.md whenever findings may be consumed by another skill or project workflow.
